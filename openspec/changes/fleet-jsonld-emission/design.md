# Design: fleet-jsonld-emission

## Source of truth

`fleet-ops/config/agent-surfaces-registry.json`. New optional per-product
fields:

```jsonc
{
  "id": "rolepatch",
  // existing: name, url, summary, publicDir, stack, productLinks…
  "headFile": "rolepatch/apps/web/src/layouts/BaseLayout.astro", // injection target
  "schemaType": "SoftwareApplication",   // or "WebSite" (content sites)
  "sameAs": ["https://github.com/sarthak-fleet/rolepatch"]        // extra entity links
}
```

`headFile` is repo-relative from the fleet root, same convention as
`publicDir`/`worker`. Products without `headFile` fall back by stack:
`spa-*`/`next-static` → `<repo>/index.html` if present; otherwise the product
is reported as `manual` and gets a generated snippet only.

## Generation

One function `buildJsonLd(product, registry)` returns:

```json
{
  "@context": "https://schema.org",
  "@graph": [
    {
      "@type": "Organization",
      "@id": "https://sassmaker.com/#org",
      "name": "SaaS Maker (Foundry)",
      "url": "https://sassmaker.com",
      "sameAs": ["<product github>", "<extra sameAs>"]
    },
    {
      "@type": "SoftwareApplication",
      "@id": "<product url>/#app",
      "name": "<name>",
      "url": "<product url>",
      "description": "<summary>",
      "publisher": { "@id": "https://sassmaker.com/#org" },
      "applicationCategory": "<registry category, optional>",
      "offers": "<registry offers, optional>"
    }
  ]
}
```

URLs use the same origin-preference chain as indexnow-submit/agent-index-audit
(`indexNowOrigin || marketingOrigin || canonicalOrigin || url`) — one shared
helper, exported from a new `fleet-ops/scripts/lib/registry.mjs` so the three
scripts stop re-implementing it.

## Injection

Marked block, idempotent (replace-if-exists, insert-before-`</head>` if not):

```html
<!-- fleet-jsonld:start (generated by apply-agent-surfaces; edit registry, not this) -->
<script type="application/ld+json">{…}</script>
<!-- fleet-jsonld:end -->
```

- Applies to stacks: `astro-static`, `next-static`, `spa-static`, `spa-hono`
  (all have a literal HTML/Astro head file).
- `opennext` (JSX): no text injection. Emit `fleet-ops/out/jsonld/<id>.html`
  and print a per-product instruction. (7 products; their layouts get the
  block added by hand once — the generated file stays the diff-able source.)

## Safety checks (post-write, per file)

1. Re-extract the block; `JSON.parse` the script contents — abort + restore
   original file on failure.
2. File still contains `</head>` exactly as many times as before.
3. `--dry-run` prints the would-be diff; `--id <product>` scopes rollout.

## Audit integration

`agent-index-audit.mjs`: fetch `/` as HTML, extract
`<script type="application/ld+json">` blocks; reported check `jsonld`:
- `pass`: ≥1 parseable block whose graph names the product (name or url match)
- `warn` (reported as skip today): none, or >1 conflicting SoftwareApplication
Not required for S-tier in v1; revisit after rollout.

## Rollout order

1. Lib + generator + `--dry-run` on all.
2. One astro-static pilot (codevetter — already has hand-written JSON-LD to
   reconcile, proving the dedup path).
3. Remaining head-file stacks, one commit per product repo.
4. opennext snippets + manual insertion pass.
5. Enable audit `jsonld` reporting.

## Commercial-truth gate

A pricing or purchase claim must be classified across four independent states. One state never implies the next:

1. **Intended model** — the product is planned to be paid.
2. **Implemented path** — pricing, checkout, or entitlement code exists.
3. **Configured provider** — products, webhooks, credentials, tax, and fulfilment are configured outside the repository.
4. **Live purchase** — an unaided customer journey has been completed against the public origin.

Pages may describe only the highest state supported by current evidence. “Paid product” is not equivalent to “buyable now,” and the absence of a script named `pay` is not evidence that a product is free.

## Purpose-first scoring contract

Landing pages are now judged first on a separate 100-point product-purpose score:

| Dimension | Points |
| --- | ---: |
| Correct product identity | 25 |
| Specific intended audience | 15 |
| Concrete value or outcome | 15 |
| Distinct product mechanism | 15 |
| Credible current proof | 15 |
| Honest next action and lifecycle | 15 |
| **Total** | **100** |

The passing floor is 85. A material contradiction fails the purpose gate regardless of arithmetic or visual quality. Purpose and visual scores are never averaged: a beautiful page for the wrong product is still a failed page.

Purpose-first repair order:

1. Missing or unusable explanation: Mashup, ChatGPT Connections, Companion Robot.
2. False lifecycle or availability: TrueHire, Verified Bases, Mobile Dev Cockpit.
3. Wrong category, audience, or mechanism: Reel Pipeline, Forecast Lab, CodeVetter.
4. Stale system definition: Significant Hobbies.
5. Consequentially incomplete promise: Site Health, SaaS Maker, PostTrainLLM, Live, Knowledge Base, Chess Coach, App Health, and Sarthak Agrawal.

Visual redesign order is considered only after those purpose corrections pass.
